# 编写剧情 JSON 与故事脚本

剧情文件使用对象根节点，包含 `StoryName`、`chapters` 和可选的 `script`、`title`、`items`、`achievements`。只接受本文这一种结构，单章故事也放进 `chapters` 列表。正式游戏的两份故事是 `data/visitor.json` 与 `data/employee.json`，共同引用 `data/logic.py`；小型接口示例已保留在 `tests/fixtures/demo/`。正式数据由 `tools/build_story.py` 编译生成，**每个完整 action 占一行**，包括只有 `function` 的动作；选项、参数、整份规则正文均内联在所属动作这一行中，文本换行写作 JSON 的 `\n`。

运行和测试命令见项目根目录的 [README](../README.md)。

## 故事选择与解锁

标题界面固定为“新游戏、载入存档、设置、退出游戏”。“新游戏”进入独立故事选择界面，再点击故事才创建其会话。选择界面不是剧情章节，不占用对白节点。

- `data/stories.json` 是菜单目录，不是第三份 story。每项包含 `id`、`name`、`file`、`description`、`cover`；需要解锁的故事另含 `unlock` 与 `locked_popup`。
- 游客故事从 `V01` 开始，员工故事从 `E01` 开始。两份 JSON 没有互相的章节，角色变量、物品和知识从各自初始状态建立。共用脚本只复用逻辑，不共享当前角色状态。
- 员工解锁条件为 `{"story": "visitor", "chapter": "V15"}`：游客完成 `V14` 海洋馆之夜，抵达 `V15` 翌日清晨即解锁，不要求取得真结局；提前离园、20:20 提前离馆、未度过这一夜的结局不会解锁。
- 未解锁时只显示目录中的 `locked_popup` 提示，复用 GUI 的阻塞弹窗控件；确认后留在选择界面，不运行员工脚本或写员工存档。
- 本地 `library.json` 保存已解锁故事与最近选择；`visitor/`、`employee/` 分别保存 `session.json`、`collection.json` 和三个手动存档槽。解锁属于玩家进度，不写入故事的 `INITIAL_STATE`，因此回退、读旧档和重开游客故事不会重新上锁。
- CLI 首次启动或 `--new` 返回 `story_selection`；`--stories` 查询目录，`--select-story visitor` / `--select-story employee` 开始故事。锁定故事返回 `status: "locked"` 和 `popup`，没有剧情段落。这是菜单状态提示，与下文剧情内 popup 自动确认的约定分开。显式指定正式员工 JSON 路径也受相同门禁约束；测试夹具等自定义 `--story FILE` 仍可独立运行。
- CLI 仅在整批操作成功后保存解锁；批处理失败不保留批次内临时到达的里程碑。GUI 每次成功推进后检查里程碑。

本次移除了旧的合并版 `data/story.json`。旧合并版快照的故事指纹与章节结构不匹配，不自动迁移；旧文件留在原处，新版使用上述子目录，不覆盖旧记录。

## 节点与执行顺序

```json
{
  "StoryName": "My Story",
  "script": "my_story.py",
  "title": {"subtitle": "欢迎来到动物园", "background": null},
  "achievements": [
    {"id": "arrived", "title": "抵达", "description": "进入第二章。"}
  ],
  "chapters": [
    {
      "id": "entrance",
      "title": "第一章 · 正常开放",
      "subtitle": "09:00 / 南门",
      "background": null,
      "contents": [
        {"id": "START", "title": "入园", "actions": [
          {"function": {"name": "visit", "args": {"place": "entrance"}}},
          {"property": "dialogue", "value": "欢迎来到动物园。"}
        ]},
        {"id": "2", "title": "岔路", "actions": [
          {"property": "dialogue", "value": "<red>请妥善保管地图。</red>"},
          {"property": "decision", "value": [
            {"text": "走向支路", "next_id": "10000"},
            {"text": "结束游览", "next_id": "END"}
          ]}
        ]},
        {"id": "10000", "actions": [
          {"property": "dialogue", "value": "你沿支路走了一小段。"}
        ]},
        {"id": "leave", "actions": [
          {"property": "chapter", "options": "to", "value": "meadow"}
        ]},
        {"id": "END", "actions": []}
      ]
    },
    {
      "id": "meadow",
      "title": "第二章 · 草食动物区",
      "subtitle": "10:00 / 蓝色步道",
      "background": null,
      "contents": [
        {"id": "START", "actions": [
          {"property": "achievement", "options": "complete", "value": "arrived"},
          {"property": "dialogue", "value": "草坪上只有温顺的动物。"}
        ]},
        {"id": "END", "actions": []}
      ]
    }
  ]
}
```

- 从 `chapters` 的第一章开始，先显示章节标题；确认后查找该章 **`id: "START"`** 作为入口，它不必位于 `contents` 第一项。执行其 actions 后，普通点击进入列表中紧邻的下一项。`id` 是字符串标识，不按数值大小排序，`"10000"` 可以用作远端小分支。
- 一次进入节点，会按顺序结算它的 `actions`；遇到 `popup` 暂停，玩家确认后从下一条动作继续。函数返回后继续下一条；多段对白合并为本节点正文，换行展示。需要等待下一次点击的对白，写进下一个节点。
- 背景、人物、音乐共同组成当前画面；多个视觉动画可以同时播放，时长不阻塞函数执行。相同对象在一批动作中多次修改，以最后的值为最终画面。
- `decision` 登记选项，不中断本节点剩余动作。因此可以在它后面写获得物品或函数。全部动作结算完成、文字读完后，GUI 显示选项；不能点击越过决策。
- `jump` 立即转到目标节点并继续结算，放弃原节点后面的动作。它不是“下次点击才跳”。跳转前本批已产生的对白保留，目标对白接在后面。
- `START`、`END` 是 **区分大小写的保留节点 ID**，每个章节必须各有一个，节点 ID 只在章内唯一。重复 ID、缺少入口或缺少终点都会在加载时报告错误。它们是节点 ID，不是 `property`。
- **一旦到达 `id: "END"`，当前故事线立即结束**，无需再点一次。顺序推进、选项的 `next_id`、普通 jump、函数返回的 jump 和物品使用触发的 jump 都遵循这条规则；END 后面的节点不会继续执行，可以在那里存放其他支线。
- END 仅作终点，`actions` 必须为空，也可直接写 `{"id":"END"}`。结束对白写在到达 END 之前的普通节点中；同批结算已经产生的对白保留，长对白在结束后仍能点击读完。START 可以承载开场动作，也可省略 actions 作为空入口。
- 分支必须通过顺序推进或显式 jump 到达 `END`。`jump` 不接受 null，尚未到 END 就走出节点列表会报错。结束后可读档、回退或重新开始，不再接受选择或物品使用。
- 未写背景、立绘、音乐时沿用已有状态；文字、语音、音效、特效和入场动画不继承。

## property 清单

共有 **16 种执行属性**；`START`、`END` 属于节点 ID，不计入 property。

| property | options / 主要字段 | GUI 展现 | CLI 展现 |
| --- | --- | --- | --- |
| `background` | `show` / `hide` / `fade in` / `zoom in`；`value` 为图片路径 | 显示 / 隐藏背景，播放指定入场动画 | 导出背景与合成场景 PNG，直接采用动画结束画面 |
| `illustration` | 同上；`value` 为完整事件插画路径 | 清空并禁止立绘叠加，等比完整显示 CG，不裁切两侧 | 输出同一完整构图，`visual_mode` 为 `illustration` |
| `character` | 同上；`slot` 为 `left` / `center` / `right` | 按位置显示立绘及动画 | 按相同位置合成到场景 PNG；隐藏后移除 |
| `dialogue` | `show`；`value` 为正文，可选 `speaker` | 对白框、逐字显示、颜色和分页 | 返回 `speaker`、完整 `text`、`text_spans`，不等待打字 |
| `popup` | `show`；`value` 为消息，可选 `title` | 居中提示，确认后执行后续动作 | 自动跳过确认，不返回弹窗消息或 popup 字段 |
| `music` | `play` / `stop`；`value` 为音频路径 | 循环播放 / 停止背景音乐 | `segment[].audio.music` 返回当前音乐文件绝对路径，停止为 null |
| `voice` | `play` / `stop`；`value` 为音频路径 | 播放 / 停止本页语音，可重听 | `segment[].audio.voices` 返回本段语音文件绝对路径列表，不播放 |
| `sound` | `play` / `stop`；`value` 为音频路径 | 播放 / 停止本页音效 | `segment[].audio.sounds` 返回本段音效文件绝对路径列表，不播放 |
| `effect` | `value` 为 `{type, duration, blocking}` | fade / flash / shake，按 blocking 阻止推进 | 不渲染特效，不等待，不输出特效指令 |
| `decision` | `value` 为选项列表；`num` 可省略 | 阅读完成后展示可用选项按钮 | 返回经过条件筛选的 `choices`，等待 `--choose` / `--choose-index` |
| `item` | `get` / `remove`；`id` 或 `value`、`count` | 更新背包；可检查和使用物品 | 返回 `inventory`，图标为文件绝对路径；`--inventory` / `--use` |
| `rules` | `value` 为 `{book_id, title, entries}` | 更新守则册，保留书签，提示已更新 | 返回本段 `rule_updates` 和当前 `rulebooks`；`--rules` / `--bookmark` |
| `function` | `value` 或独立 `function` 字段 | 无独立控件，执行函数并呈现返回动作 | 无独立输出，执行相同函数并呈现返回动作；不暴露内部变量 |
| `jump` | `to`；`value` 为本章节点 ID | 立即进入目标节点；END 结束故事线 | 采用相同跳转及结束规则，返回到达节点的内容 |
| `chapter` | `to`；`value` 为章节 ID | 新背景、章节标题页，自动存档 | 作为章节进度点返回 `chapter_intro`、`chapter_info` 并自动存档，`--continue` 进入正文 |
| `achievement` | `register` / `complete` | 登记到成就面板，首次完成时提示 | 返回 `achievements` 及本段 `new_achievements`；可用 `--achievements` 查询 |

两个入口共享核心状态和执行规则。GUI 的确认步骤、打字时长、动画和音频播放不会变成 AI 的额外操作要求；章节入口则保留为明确的进度与存档边界。CLI 始终在实际选择 / 可用物品处等待，弹窗本身不会打断自动推进。

CLI 的每段 `audio` 包含 `music`（路径或 null）、`voices` / `sounds`（路径列表）。这些是音频素材引用，不是自动转写或对声音内容的猜测。若声音承载必须能以文字读取的剧情线索，请同时写入 `dialogue`。屏幕特效和入场动画同样属于表现层，需要让 AI 获知的剧情变化应写成正文或规则。

图片和脚本路径相对剧情文件所在目录。动画时长 `args` 可以写数值秒数，或 `"0.5s"`，范围为 `(0, 30]` 秒。文字支持配对的 `<red>`、`<green>`、`<blue>` 标签及嵌套；CLI 输出不带标签的正文和 `text_spans`，其中 start/end 为可见 Unicode 字符的半开区间，color 为 RGB。

## 背景、立绘与事件插画

`art/backgrounds/` 只放可复用的园区、设施、动物和异常环境，不将主角团或主要员工画进背景。普通对话使用背景加人物立绘，`character.slot` **默认 `left`**；只有明确的多人调度才指定其他位置。观察动物、物品或环境时主动隐藏立绘。

`art/illustrations/` 放重要动作的完整事件构图，`art/endings/` 放结局插画，`art/covers/` 放开场及路线封面。人物已经画在插画里，所以引擎会清空现有立绘，并忽略插画期间的 `character show`；GUI 和 CLI 渲染层也执行这一约束。切回 `background` 后不恢复旧立绘，需要显式显示下一位说话者。

```json
[
  {"property": "background", "value": "art/backgrounds/rabbit_day.png"},
  {"property": "character", "value": "art/characters/lin_day.png"},
  {"property": "dialogue", "speaker": "林夏", "value": "那只像你上周通宵以后。"}
]
```

重要事件发生的节点改用 `{"property":"illustration","value":"art/illustrations/blue_rescue.png"}`，后续对白沿用插画，不再添加立绘。事件结束时用 `background` action 返回环境。`illustration hide` 清除插画并回到无背景状态，不自动恢复之前的场景。

章节可设置 `"visual_mode":"illustration"`，让章节 `background` 从标题页到正文都按完整插画处理；默认值是 `background`。结局与路线封面使用插画模式。事件图不要提前放在普通章节标题页，以免展示玩家还没选择的结果。

GUI 正文中按 **Tab** 隐藏文字和控件查看完整画面，再次按键或点击只恢复界面，不推进剧情。CLI `segment[].visual_mode` 明确区分两种模式；插画时 `background_image` 与 `scene_image` 内容相同，没有立绘。

## 弹窗事件与新手引导

`popup` 在屏幕中央显示消息，暂停当前节点的后续动作。适合新手引导、获得物品的提示、规则更新提醒。`value` 必须是非空字符串，支持换行及与对白相同的 `<red>`、`<green>`、`<blue>` 配对颜色标签，可以嵌套。`title` 是可选的纯文字标题，默认“提示”；`options` 可省略，填写时只能是 `show`。

```json
{
  "property": "popup",
  "options": "show",
  "title": "游园提示",
  "value": "<green>规则已更新，请查看。</green>\n通过<blue>规则界面</blue>查看收集到的所有告示和规则。"
}
```

在对应的获得物品或规则更新 action **之后**放置弹窗；这些事件不会自动生成阻塞弹窗，由剧本决定什么时候提醒。例如以下 actions 在已有 `map` 物品定义时可用：

```json
[
  {"property": "item", "options": "get", "value": "map"},
  {"property": "popup", "value": "已获得<blue>游园地图</blue>，可在背包中使用。"},
  {"property": "popup", "value": "通过规则界面查看收集到的所有告示和规则。"},
  {"property": "dialogue", "value": "你收好地图，继续向园区走去。"}
]
```

获得地图后弹出第一条提示，确认后才弹出第二条，再确认后执行后续对白。弹窗也可放在选项 actions、物品 on_use 中，或由脚本返回；支持 `when` 条件和通用 `function` 字段。后面的函数、物品增减、jump、chapter 都等确认后才执行，确认不会重新执行弹窗之前的动作。

GUI 点击弹窗或“知道了”，也可按空格 / 回车确认；长消息分页显示，最后一页确认才继续剧情。弹窗期间背景菜单、选择和物品操作暂停，避免误点穿透。此前已经产生的对白保留，确认后仍可继续阅读；连续多条 popup 会逐条等待确认。弹窗只是临时提示，规则的收集仍由 `rules` action 负责。

CLI 将 popup 作为人类界面的引导提示处理：自动确认并继续，不返回弹窗文字、颜色或 `popup` 字段，也不会出现 `awaiting_popup` 状态。连续弹窗全部自动越过。前后正文、规则更新、成就和音频引用仍会保留，不会因过滤弹窗而丢失。`popup` 不应独占剧情线索或实际规则；需要 AI 读取的内容请使用 `dialogue` / `rules`。

弹窗及未执行的动作队列随存档保存。GUI 中途退出后可以继续上次进度，回到同一个待确认弹窗；长消息从该弹窗第一页重新显示。读档 / 回退不会重放已经执行过的函数或重复发放物品。GUI 剧情回顾也会记录弹窗消息。CLI 加载到弹窗快照时会自动完成确认，再返回有效剧情内容；继续执行的函数和状态更新照常记录，重新查看当前结果不会重复执行。

## 章节、标题与剧情图

`chapters` 中每章的 `id`、`title`、`contents` 必填，`subtitle`、`description`、`ending`、`background`、`visual_mode`、`achievements` 可选。章节 ID 全故事唯一；`jump` 和选项 `next_id` 只查找本章节点，同名节点可出现在不同章节。节点的可选 `title` 用作普通存档点名称，省略时使用正文摘要或 ID；章节树卡片使用章节元数据中的 `title`。

根节点 `title` 控制游戏标题页，包含可选 `subtitle` 和 `background`。章节 `background` 控制该章标题页及初始正文背景，填图片相对路径；省略或设为 null 时使用界面的导览图形占位，CLI 导出纯色占位。正文可以用 `background` action 换图。

```json
{"property": "chapter", "value": "meadow"}
```

`chapter` 立即终止当前动作队列，进入目标章标题页，并自动保存入口。此时还没有执行新章 START 中的函数；GUI 点击“进入章节”，CLI 使用 `--continue` 后执行 START。**chapter 会清空当前对白**，所以本章最后一段对白请放在它之前的独立节点。无论来自正文、选项、函数还是物品使用，都遵循此约定。

跨章保留故事 state、物品、守则、书签、成就；背景换成新章元数据中的图片，立绘和音乐清空，由新章动作重新配置。到达 END 只结束本条故事线，不自动进入列表中的下一章。需要继续下一章时，显式写 chapter。

GUI 设定中的“剧情图”是一棵**以章节为节点的树**：父章节在上方居中，子章节在下一层并排分叉。章内的对白、物品事件和普通存档点不占图节点；完整存档点仍可以通过 CLI 的 `--list-load-point` 查询。

章节卡片上的标题使用 `title`，下面一行简介使用 `description`，未填写时回退到 `subtitle`。`subtitle` 继续用于章节标题页的时间 / 地点等说明。`ending` 可省略（普通章节），或填写 `normal`（一般结局）、`death`（死亡结局，图中以红色标识）。例如：

```json
{
  "id": "ending-death",
  "title": "结局 · 围栏之后",
  "subtitle": "17:40 / 员工通道",
  "description": "你跟随声音，走进了不向游客开放的区域。",
  "ending": "death",
  "contents": [
    {"id": "START", "actions": [
      {"property": "dialogue", "value": "围栏在身后合拢。这次游园没能迎来归途。"}
    ]},
    {"id": "END"}
  ]
}
```

不同分支结局建议各自配置成独立章节，通过 `chapter` action 跳转到对应 ID。`ending` 是展示元数据，不替代 END 的终止逻辑。普通章节抵达 END 时，图中也会标为一般结局。

树只展示已经进入的章节和路线，不提前透露未来章节。卡片关联该次进入章节时的快照，选中后点击“从章节入口继续”读档；物品、变量、守则、成就都会回到该入口的状态。当前位置仍逐页自动保存；可导航检查点保留章节、选择、弹窗、结局和手动存档，避免长篇故事逐页复制整段历史。

相同章节由不同路线到达时，保留不同的树节点及存档，不把状态混合。同一份章节入口反复读取或重复游玩时复用树节点；回退不会生成从后章倒连到前章的错误边。跨路线汇合的章节会分别出现在各自父分支下，以保持树结构。单独导入的手动存档若没有对应章节入口记录，会作为可恢复的独立根节点显示，按钮标为“从记录处继续”。

树可拖动空白处平移，滚轮上下移动，Shift + 滚轮左右移动，Ctrl + 滚轮或加减按钮缩放，“适应窗口”显示全树。CLI 的 `--flowchart` 返回同一棵树的 `tree` 数据（`roots`、`nodes`，节点包含 `parent`、`children` 和 `load_point`）以及带分支线的 `tree_text` 文本。

## 成就注册与完成

根节点的 `achievements` 在新游戏开始时注册，章节元数据的 `achievements` 在进入该章节时注册。也可以在执行过程中注册：

```json
{"property": "achievement", "options": "register", "value": {
  "id": "helper", "title": "交接完成", "description": "将样本交给巡查员。"
}}
```

完成时引用成就 ID：

```json
{"property": "achievement", "options": "complete", "value": "helper"}
```

成就 ID 在整部故事中共享。注册定义需要非空 `id`、`title`、`description`；相同定义可重复注册，不会重置完成状态，相同 ID 的不同定义会报错。完成未注册的成就会报错。重复 complete 不重复提示；可以使用 `when` 限制完成条件，也可由脚本返回这些 actions。

GUI 在“设定 → 游园成就”展示当前已注册成就，首次完成时提示；CLI 的正文观察包含 `new_achievements`，`--achievements` 查询完整状态。核心执行器中的成就仍随进度恢复。Session 另外维护 `collection.json`，把已经达成的成就、实际读过的文档及完成结局的 CG 跨周目保留；GUI 展示这份累计收藏。资料馆不参与角色知识和剧情判定，不会把另一条线的规则自动注入当前存档。

## 故事脚本

上述 JSON 对应的 `my_story.py`：

```python
INITIAL_STATE = {"visited": [], "route": None}


def visit(state, args, context):
    state["visited"].append(args["place"])


def choose_route(state, args, context):
    state["route"] = args["route"]
```

脚本无需导入 core。`INITIAL_STATE` 和函数内的状态结构都由故事决定，允许嵌套字典、列表和 JSON 基本值。

函数统一接受 `(state, args, context)`：

- `state`：本次调用的故事状态副本，可以修改，成功后提交到游戏状态。
- `args`：JSON 中的参数，默认 `{}`。
- `context`：普通字典，包含当前 `chapter_id`、`page_id` 和背包数量 `inventory`；修改这个字典不会修改核心状态。
- 返回 `None` 表示仅修改 state。也可返回 action 列表，插入在调用点之后、原下一条之前执行；简单的固定对白直接写在 JSON 下一条即可。

推荐写法：

```json
{"function": {"name": "visit", "args": {"place": "entrance"}}}
```

可以把 `function` 写在普通 action 上，它会先执行，再执行该 action。选项也可以带函数，只有选中时才执行：

```json
{
  "text": "按地图前进",
  "when": {"read_map": true},
  "function": {"name": "choose_route", "args": {"route": "map"}},
  "next_id": "10000"
}
```

选项可包含 `actions`，执行顺序为函数、选项 actions、`next_id` 跳转；前面的动作若已执行 jump 或 chapter，会放弃剩余队列。`when` 是 state 中顶层键的相等条件，不执行表达式。运行到 decision 时必须至少有一个可见选项。

`function` 使用 `{name, args}`，也可以只写函数名字符串。

## 守则与书签

守则按册子和条目的稳定 ID 更新，放在相应剧情节点的 actions 中：

```json
{
  "property": "rules",
  "value": {
    "book_id": "visitors",
    "title": "游客守则",
    "entries": [
      {"id": "01", "text": "请妥善保管随身地图。"},
      {"id": "02", "text": "这里填写玩家新获得的规则。"}
    ]
  }
}
```

首次出现的 book_id 创建册子；后续相同 ID 补充内容。同册中相同条目 ID 更新正文并保留书签，新 ID 追加条目。book_id 和条目 ID 不能包含冒号，book_id 不能使用界面保留名 `__bookmarks__`。

玩家只能查看已经执行到的规则更新，不能提前看到未来节点中的守则；书签引用形式为 `book_id:entry_id`。守则与书签随读档、回退恢复。

## 物品的随时使用

物品可以在获得时内联定义：

```json
{
  "property": "item",
  "options": "get",
  "id": "map",
  "value": "map.jpg",
  "name": "Map",
  "desc": "A map to help you navigate the world.",
  "consume": 0,
  "on_use": [
    {"function": {"name": "read_map", "args": {}}},
    {"property": "dialogue", "value": "你展开了地图。"}
  ]
}
```

`value` 在内联定义中是可选的物品图像；推荐显式写稳定的 id，省略时用 name。之后增减同物品可写 `{"property":"item","options":"get","value":"map"}`。也可在故事根节点 `items` 中集中放 `{id, name, description, icon, consume, on_use}` 定义。

- `on_use` 是该物品在任何剧情节点的使用动作；无需在每一页重复注册。可以在普通对白、选择页，以及文字尚未显示完时打开背包使用。
- `consume` 默认 0；为正整数时，每次使用扣除相应数量。必须持有至少一件，数量不足时不可用。
- 若把 `function` 直接写在 item action 上，它是 **使用时** 的处理函数，不会在获得物品时调用；使用时先调用它，再执行 `on_use`。
- 使用动作里的函数执行后，立即接着结算后续对白、画面等动作。只想改变状态时，可以不配置对白。
- 无跳转的使用暂时插入一段事件；读完后继续一次，返回被中断节点的正文和选项，保留使用导致的变量、背包、场景改变。不会重复执行原节点的获得物品和函数。
- 使用动作中出现 `jump` 或 `chapter` 时，直接进入新剧情，放弃返回原节点。需要多次点击展开的物品支线，可以 jump 到独立节点，然后在支线尾部自行 jump 汇合。
- 多次使用允许嵌套返回。读档保存返回位置；回退会一起撤销消耗、变量更新和物品事件。
- 章节标题页和当前故事结束后不能使用物品；进入正文后恢复可用状态。

## 保存与函数边界

故事和脚本的内容决定存档版本指纹。存档记录故事 state、背包、画面、操作路径、被中断节点，以及每次函数调用的输入和结果。恢复与回退重建时使用记录的结果，不重新调用函数。再次主动前进、使用或重新开始时才产生新调用。脚本源码和剧情内容进入版本指纹，修改后旧档会拒绝读取。

同一次运行只加载一个故事脚本模块，切换章节不会重新 import，因此模块本身不会因换章消失。但 CLI 每次命令都是新 Python 进程，普通模块全局变量不能跨进程存活，也不会自动进入存档。需要跨章、跨命令、读档和回退一致的运行状态必须放进 `INITIAL_STATE` / 传入的 `state`；常量和函数可以保留在模块全局。回调的职责是修改 state、返回 actions；文件写入、网络请求等外部副作用不属于游戏事务，发生异常或撤销进度时无法自动撤回。脚本模块的顶层代码在加载故事时会执行，因此顶层只放定义和初值。这里动态加载的是本地 Python 脚本，没有做 Python 沙箱。


## 批量验证与资料馆

CLI 的 `--batch OPERATIONS_JSON` 接受显式操作列表，可用于回归完整路线。它不跳过条件、不编辑状态、不自动选择答案。选择序号仍从 1 开始。

```json
[
  {"action": "continue"},
  {"action": "continue"},
  {"action": "choose", "index": 1}
]
```

物品操作为 `{"action":"use","item":"ITEM_ID"}`。一批最多 3000 步；每一步都经过相同 Session / Engine API。如果某一步非法，不提交这批剧情进度。输出包含终点观察、`batch_steps` 和完整批次文字回放文件 `batch_transcript`。GUI 确认弹窗在显式批次中同样用 continue；单步 CLI 仍按前述约定自动确认弹窗。

`--collection` 读取本会话目录下的跨周目资料馆，独立于 `--rules` 所查询的当前角色知识。`tools/check_routes.py` 会从真实选择生成验证用操作文件，不通过直接指定结局或篡改变量走捷径。

## 正式游戏素材

背景、立绘、物品与 CG 均位于 `data/art/`。同一角色的身份以人物母版为准。人物立绘在环境观察页面隐藏，结局使用各自的完整 CG；夜间对白框使用暗色样式。

剧情仍以节点动作驱动，不从图片里的文字识别规则。完整规则作为单次 rules 更新收录，可选纸条仅在主动调查后更新。源码与素材说明见 `CREDITS.md`。
